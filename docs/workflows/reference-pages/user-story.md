# Worked user story: React reference pages

## What this teaches

A user story starts with the person’s need. It does not start with “build a Header” or “make four pages.” Those are implementation decisions that come later.

## Example

As a person reviewing or planning an application,
I want to compare clear examples of page layouts and navigation arrangements,
so that I can choose a structure that fits the page’s purpose without adding unnecessary complexity.

The examples should help me understand what changes on a smaller screen, what each region is for, and what behavior must remain accessible and usable.

## Boundaries

This story is about reviewing and learning from the reference experience. It does not promise that the demo routes can be copied into a product application unchanged, and it does not make every layout appropriate for every task.

## Why it matters

A beginner should be able to look at the running pages, name the visible regions, compare the tradeoffs, and describe the intended behavior before choosing components or writing code.
