# Role guides

The kit serves several roles without assuming that one role already understands the whole delivery process.

- Business stakeholders need tangible examples and plain-language explanations.
- Business analysts need structured ways to describe goals, rules, and acceptance criteria.
- Designers need reusable structure, states, and content constraints.
- Developers need explicit implementation contracts and ownership boundaries.
- Testers need observable behavior, scenarios, and quality expectations.

The guidance should help roles collaborate around the same pattern rather than create disconnected interpretations.
